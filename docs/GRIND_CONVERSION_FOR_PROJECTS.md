# 磨豆機刻度換算 — Projects 查表文件

> **給 Claude Projects 使用，無需執行任何程式碼。** 純查表 + 簡單算術即可把任一支援
> 磨豆機的刻度，換算成另一台（含模型原生軸 **1Zpresso ZP6**）。
>
> **唯一真相源是 [`models/grind.py`](../models/grind.py)。** 本文件的所有數字由它生成，
> 與 CLI（`--grinder`）、webapp（換算器）的輸出 **byte-identical**。若 `grind.py` 改了，
> 重新生成本文件即可，**不要在這裡手改數字**。

---

## 0. 這份文件能做什麼、不能做什麼

- ✅ 把「A 機刻度 X」換成「B 機刻度 Y」，泡起來味道相當。
- ✅ 雙向、任意兩台之間（一律經過共同的「對齊等級 level」中轉）。
- ❌ 不評分、不預測風味、不碰沖煮模型。**只做刻度翻譯。**
- ❌ 不是精校儀器：列與列之間是估算（見 §6 不確定性）。

支援 7 台：**1Zpresso ZP6**（原生軸）、Comandante C40、Mahlkönig EK43s、
Baratza Forte BG、Fellow Opus、Fellow Ode (SSP)、Fellow Ode Gen 2。

## 1. 核心觀念：7 級「味道對齊」對照

`docs/刻度比較.xlsx` 量了 7 個**對齊等級**（level 1 = 最細 → level 7 = 最粗）。
每一**列**是同一支豆在各機上泡到口感相當的實測刻度。換算永遠是三步：

```
來源刻度  ──①──▶  對齊等級 level (1..7)  ──②──▶  目標刻度
```

- **錨點列（下表 7 列）是實測、最可信。**
- 落在兩個錨點之間 → **線性內插**（估算，見 §6）。

## 2. 精確換算演算法（線性內插，可手算）

設來源機 anchors = `A[1..7]`、目標機 anchors = `B[1..7]`（見 §3 陣列）。

**① 來源刻度 → 數值 v**
- 數值機：`v` = 刻度數字本身。
- Forte BG 輸入 = 「macro 數字 1–10 緊接**剛好一個**字母 A–Z」，例 `6H`、`10S`。
  解析：先去頭尾空白，比對 `^([1-9]|10)([A-Za-z])$`（大小寫皆可、查表前轉大寫；macro 數字貪婪，`10X` 取 macro=10 而非 1）；中間有空白或分隔（`6-H`、`6 H`）、無字母、或多於一個字母 → 非法。
  `micro序`：A=0, B=1, …, Z=25，`v = (macro − 1) × 26 + micro序`。
  （例 `6H` → `(6−1)×26 + 7 = 137`。`0–259` 只是**合法 label 語法範圍**；index < 74 或 > 200
  仍超出錨點範圍、會在 ⑤ 拿到 `~`。macro 不在 1–10、沒有字母、或多於一個字母 → 非法輸入。）

**② v → 對齊等級 level**（先判斷三種情形，再套公式）

1. `A[1] ≤ v ≤ A[7]`（**範圍內**）：找包夾的相鄰錨點 `A[i] ≤ v ≤ A[i+1]`（`i` = 下錨點 level，1..6），
   ```
   level = i + (v − A[i]) / (A[i+1] − A[i])
   ```
   （v 剛好等於某內部錨點 `A[k]` 時，相鄰兩 bracket 同值 = 整數 `k`，**取任一即可**；`v = A[1]` → `level = 1.0`、`v = A[7]` → `level = 7.0`，皆算範圍內、不加 `~`。）
2. `v < A[1]`（**太細，超範圍**）：`level = 1 + (v − A[1]) / (A[2] − A[1])`（會 < 1，可能是 0 或負）。
3. `v > A[7]`（**太粗，超範圍**）：`level = 7 + (v − A[7]) / (A[7] − A[6])`（會 > 7）。

三種情形互斥、用**嚴格**不等號分界：`v = A[1]` 或 `v = A[7]` **永遠算情形 1**（不加 `~`），只有 `v` 嚴格小於 `A[1]` 或嚴格大於 `A[7]` 才是情形 2/3。**Forte 來源時，這裡的 `v` 是編碼後的 index、用 Forte 的 index 陣列 `[74…200]` 判斷**（不是拿 macro 數字或原字串比）。

> **外插原則（來源、目標兩側同一招）：** 超範圍**永遠只延長最外側那一段**的斜率——
> **來源側**（② 第 2/3 種情形）太細用 `A[2]−A[1]`、太粗用 `A[7]−A[6]`；
> **目標側**（③）`j` 夾在 1 或 6，等於用 `B[1]→B[2]`（太細）或 `B[6]→B[7]`（太粗）那段延長。
> **沒有 `A[0]` / `A[8]`**：超範圍時重用最外側那段的寬度當分母（太細 = 第一段 `A[2]−A[1]`、太粗 = 最後一段 `A[7]−A[6]`），別把 in-range 模板 `A[i+1]−A[i]` 硬套到 `i=7` 去找不存在的 `A[8]`。
> **不要**改用全表平均斜率或全域擬合——這也是 §6 #1 反對「為換算去跑回歸」的原因。

**③ level → 目標數值 out**
令 `j = floor(level)`，**夾在 1..6**（超範圍時 `j` 自動停在 1 或 6，正好延長端段）：
```
out = B[j] + (level − j) × (B[j+1] − B[j])
```
（`level − j` 在低端可為負、高端可 > 1 —— **這是正常的，別 clamp**。）

**④ 編碼 + 取整（顯示）**
- 數值機：half-up 四捨五入到該機小數位 `d`：`floor(out × 10^d + 0.5) / 10^d`。
  C40 `d=0`、ZP6 / EK43s / 三台 Fellow `d=1`。數值機**永不 clamp**：超範圍（`~`）時 out **可以低於該機 level-1 錨點、甚至為負**，照算照報（例：ZP6 `1.0`→C40 = `11`，比 C40 最細錨點 `14` 還細；ZP6 `1.0`→EK43s = `2.8`，比 `4.4` 還細）。**別因為「看起來太細／是負的」就把它夾回錨點** —— 那正是被禁止的 clamp。
  （half-up 公式對**負的** out 仍照字面算：`floor` 往 −∞ 取整、`.5` 進位偏 +∞，所以負值的 `.x5` 結進方向和正值相反；**逐字套公式即可，別改用口語「四捨五入到絕對值較大端」**。負 out 只在極細外插才出現，實務罕見。）
- Forte BG（**唯一不套上面「數值機 half-up」規則的機台**，直接走這條編碼；out 若 < 0 也照字面 `floor(out+0.5)` 後夾到 0 → `1A`）：`idx = floor(out + 0.5)`（夾在 0..259），再
  `macro = floor(idx ÷ 26) + 1`（**先 floor / 無條件捨去，不是四捨五入**）、
  `micro序 = idx − (macro−1) × 26`（保證落在 0..25）→ 字母（0→A …25→Z）。
  **若 micro序 算出負數或 > 25，就是 macro 誤用四捨五入而非 floor。**
  （`0..259` 的夾制保證輸出 macro 永遠是 1–10（idx 234–259 = macro 10），**不會**算出 `11A` 這種 macro ≥ 11。
  輸出 label 細於 `3W`(74) 或粗於 `8S`(200)（如例 4 的 `9F`、或 `2A`）仍是合法機台設定，但**必帶 `~`**；只有極端外插才會 `out > 259` 或 `< 0`、被夾到 `10Z`/`1A`，那時別把飽和值當精確。）

**⑤ 超出範圍標記**
只要 `v < A[1]` 或 `v > A[7]`（即 ② 走了第 2 或第 3 種情形、level 落在 1..7 之外），結果前加 **`~`**
（`in_range = false`）。其餘照 ②③④，沒有額外公式。

**⑥ 非法 / 無法解析的輸入**
數值機收到非數字，或 Forte label 不過 `^([1-9]|10)([A-Za-z])$`（macro 不在 1–10、缺字母、多字母、含分隔或空白）→ **停下來請使用者重新輸入，不要猜、不要夾、不要當 0**。
這跟「超範圍」**不同**：超範圍是合法值、照算只是加 `~`；非法是根本解析不出 `v`、沒有答案可給。

## 4. Worked examples（步驟全展開，含超出範圍兩端、低於目標最細錨點、Forte 來源超範圍、負 out）

**例 1 — Comandante C40 `18` → ZP6**
- ① v = 18。
- ② C40 `17(lv3) ≤ 18 ≤ 20(lv4)`：`level = 3 + (18−17)/(20−17) = 3 + 1/3 = 3.333`。
- ③ ZP6 `j=3`：`out = 2.8 + (3.333−3)×(3.7−2.8) = 2.8 + 0.333×0.9 = 3.07`。
- ④ ZP6 d=1 → **`3.1`**。

**例 2 — ZP6 `4.8` → Forte BG**
- ① v = 4.8。
- ② ZP6 `4.4(lv5) ≤ 4.8 ≤ 5.4(lv6)`：`level = 5 + (4.8−4.4)/(5.4−4.4) = 5.4`。
- ③ Forte index `j=5`：`out = 137 + (5.4−5)×(160−137) = 137 + 0.4×23 = 146.2`。
- ④ `idx = floor(146.2+0.5) = 146` → `macro = floor(146÷26)+1 = 5+1 = 6`、`micro序 = 146 − 5×26 = 16 = Q` → **`6Q`**。

**例 3 — Forte BG `6H` → Fellow Ode Gen 2**
- ① `6H` = `(6−1)×26 + 7 = 137` = 正好 level 5 的錨點。
- ② `level = 5.0`。
- ③ Ode Gen 2 level 5 錨點 = `4.0`。
- ④ → **`4.0`**。

**例 4（超出範圍 / 高端）— ZP6 `7.5` → Forte BG**
- ① v = 7.5。
- ② `v > A[7]=7.0`（太粗，情形 3）：`level = 7 + (7.5−7.0)/(7.0−5.4) = 7 + 0.5/1.6 = 7.3125`。
- ③ Forte index `j` 夾在 6：`out = 160 + (7.3125−6)×(200−160) = 160 + 1.3125×40 = 212.5`。
- ④ `idx = floor(212.5+0.5) = 213` → `macro = floor(213÷26)+1 = 8+1 = 9`、`micro序 = 213 − 8×26 = 5 = F`。
- 加 `~`（外插）→ **`~9F`**。

**例 5（超出範圍 / 低端）— ZP6 `1.5` → EK43s**
- ① v = 1.5。
- ② `v < A[1]=1.8`（太細，情形 2）：`level = 1 + (1.5−1.8)/(2.1−1.8) = 1 + (−0.3)/0.3 = 0.0`。
- ③ EK43s `j` 夾在 1：`out = 4.4 + (0.0−1)×(5.0−4.4) = 4.4 − 0.6 = 3.8`。（3.8 比 EK43s 最細實體刻度 4.4 還細；§2④ 數值機不 clamp，照報並加 `~`。）
- ④ d=1 → `3.8`，加 `~` → **`~3.8`**。

**例 6（超出範圍 / 低於目標最細錨點）— ZP6 `1.0` → C40**
- ① v = 1.0。
- ② `v < A[1]=1.8`（太細，情形 2）：`level = 1 + (1.0−1.8)/(2.1−1.8) = 1 + (−0.8)/0.3 = −1.667`。
- ③ C40 `j` 夾在 1：`out = 14 + (−1.667−1)×(15−14) = 14 + (−2.667)×1 = 11.33`。
- ④ C40 d=0 → `11`，加 `~` → **`~11`**。（`11` 比 C40 最細錨點 `14` 還細——**這是正確的，別 clamp 回 14**；level 也允許是負的。）

**例 7（超出範圍 / 來源是 Forte BG）— Forte BG `3M` → ZP6**
- ① 先編碼：`3M` → `v = (3−1)×26 + 12 = 64`（micro `M` = 12）。
- ② 對 **Forte index 陣列** `[74, …, 200]` 判斷：`v = 64 < A[1] = 74`（太細，情形 2）：
  `level = 1 + (64−74)/(82−74) = 1 + (−10)/8 = −0.25`。
- ③ ZP6 `j` 夾在 1：`out = 1.8 + (−0.25−1)×(2.1−1.8) = 1.8 + (−1.25)×0.3 = 1.425`。
- ④ d=1 → `1.4`，加 `~` → **`~1.4`**。
- 注意：`~`／範圍判斷是對**編碼後的 index**（64 vs 74）、用 **Forte 的 index 陣列**，不是對 macro 數字或原字串。

**例 8（極端外插 / 負 out 示範）— Forte BG `1A` → ZP6**
> 純粹示範公式對**負值**的行為；`1A` 遠細於 Forte 最細錨點 `3W`，ZP6 會算出負刻度（物理上不存在），實務不會用到——但公式照算、不特判。
- ① `1A` → `v = (1−1)×26 + 0 = 0`。
- ② `v = 0 < A[1] = 74`（太細，情形 2）：`level = 1 + (0−74)/(82−74) = 1 − 9.25 = −8.25`。
- ③ ZP6 `j` 夾在 1：`out = 1.8 + (−8.25−1)×(2.1−1.8) = 1.8 + (−9.25)×0.3 = −0.975`。
- ④ half-up d=1 **照字面套**：`floor(−0.975×10 + 0.5)/10 = floor(−9.25)/10 = −10/10 = −1.0`（`floor` 往 −∞，所以 −9.25 → −10）。加 `~` → **`~−1.0`**。
- 對照 `.x5` 結進：若 out = `−1.25`，`floor(−12.5 + 0.5)/10 = floor(−12.0)/10 = −1.2`（**不是** −1.3）——負值結進偏 +∞，和口語「四捨五入到絕對值較大」不同，逐字套公式就對。

## 5. 快速查表（細表，對齊等級每 0.1 一列）

**這是「向前」生成的表（對齊等級 → 各機四捨五入後刻度），是 ±1 列的速查、不是精算。**
用法：**只在某台「具名機台」欄**找到（最接近）你的刻度 → 同一列橫讀到目標欄。
**絕不要拿你的輸入去比對最左的 `L*` 等級欄**（它不是任何機台的刻度）。要與工具**完全一致**，請用 §2 演算法。

> ⚠️ **四個陷阱：**
> 1. **最左欄是「對齊等級」（已標成 `L1.0`…`L7.0`），不是刻度。** `L` 值（1.0–7.0）會和真實刻度
>    **數值重疊**（ZP6 1.8–7.0、Opus 2.2–7.1、Ode 3.0–7.2…），所以**別拿你的數字橫掃整列找**：
>    每次查表第一步先鎖定**欄頭是你機台名稱**的那一欄，只在那一欄裡找。要查「ZP6 4.8」→ 到 **ZP6 欄**
>    找 4.8（落在 `L5.4` 那列）→ 橫讀 Forte BG = `6Q`；別把 `L5.4` 當刻度、也別把 ZP6 欄的 4.8 當等級。
>    **反例（錯誤示範）：** 看到「ZP6 4.8」就在最左欄找到 `L4.8` 列、橫讀 Forte = `6E` —— **錯**；
>    `L4.8` 是等級不是 ZP6 刻度，正解要在 **ZP6 欄**找 4.8（`L5.4` 列）得 `6Q`。
> 2. **欄位不可逆（多列對同一刻度）。** 刻度被四捨五入後，同一來源刻度可能出現在**多列**（例：
>    ZP6 `4.3` 同時在 `L4.8` / `L4.9` → Forte `6E` / `6F`，差 1 micro；ZP6 `2.0` 橫跨 `L1.5`–`L1.8` 四列）。
>    **命中多列（不論幾列）時，速查給不出唯一解 —— 請回 §2**。（真的只想要近似、不回 §2 時，才退而
>    取**最細（`L` 最小）**那列當慣例；但唯一正解永遠是 §2。）
> 3. **在範圍內、但落在兩印出列之間（或兩列等距）：** 先把你的輸入**四捨五入到該欄小數位**再找；仍找不到
>    精確值代表你落在取樣級之間 —— 回 §2 算，**不帶 `~`**（你仍在 `L1.0`–`L7.0` 範圍內）。
> 4. **超出範圍（先做這個邊界比較，再判斷是情形 3 還是 4）：** 拿你的值和**該欄 `L1.0` / `L7.0` 兩格**比大小——
>    **比 `L1.0` 格更細、或比 `L7.0` 格更粗** = 超範圍，回 §2 算、答案**帶 `~`**；**別硬塞進 `L1.0` / `L7.0` 列**
>    （那會吞掉 `~`、把超範圍偽裝成範圍內）。只有介於兩印出列之間才是情形 3（不帶 `~`）。
>
> **Fellow 三欄**（Opus / Ode / Ode Gen 2）的值是**顯示用四捨五入、非實體刻點**；回報計算值即可，
> snap 到最近刻點是你在機器上做的事（見 §6 #2）。

## 6. 不確定性與紅線（重要 — 別跳過）

1. **錨點之間是估算，約 ±1 步級不確定。** 我實測過：把線性內插換成平滑曲線（regression /
   PCHIP），**顯示刻度最多會差 ~1 個 C40 click、~2 個 Forte micro、~0.1–0.3 個 Fellow dial**。
   重點是 —— 這不是「線性比較差、回歸比較準」：你的 7 個點**之間沒有資料**，線性與平滑誰對
   都沒證據。**所以不要為了換算去跑回歸校正**（它只是把一個沒根據的曲線假設換成另一個）。
   要真的縮小列間誤差，唯一辦法是**量更多味道對齊的錨點**，不是在同樣 7 點上換內插法。
   → 實務：**最信任錨點列**，列間值當起點、靠舌頭微調 1–2 步。

2. **Fellow 三台的「小數」是分段刻點（非連續 dial）。** §2 照樣算出 1 位小數值（如 `4.7`）——
   **永遠回報這個計算值，計算階段不要 snap**。你實機去轉時 Fellow 是跳格的，設最近的實體刻點即可；
   本文件**不提供**各 Fellow 的實體刻點格，snap 是你在機器上的手動步驟、不在換算範圍內。
   （§5 的 Fellow 欄也已是顯示用四捨五入，非刻點對齊。）

3. **換算是 display-only 近似。** 各機刀盤型式不同（ZP6 conical 手磨、EK43s/Forte 54mm
   flat、Fellow SSP），粒徑分布寬窄有差；同一列泡出來仍可能略不同（正常範圍）。刀盤磨損、
   豆種、焙度、磨機溫度也會讓實際 µm 漂移。

4. **副機的杯子不要餵迴圈 / §4 問卷的 `overall`、`attributes_vs`。** 沖煮模型的迴圈只在
   **ZP6** 上跑（那是它校準的軸）。把非 ZP6 機台的杯子評分餵進迴圈，會把磨豆機之間的粒徑
   分布差異**偽裝成風味漂移**，把冠軍往錯誤方向推。副機就是「換個地方泡同一個冠軍」來喝，
   要記錄可留 `comment` + `stars`，但**留空 `overall` 與 `attributes_vs`**。
