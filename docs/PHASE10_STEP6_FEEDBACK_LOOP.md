## 0. 一句話

把系統從「一次性推薦最佳配方」改成 **配方產生機** —— 一代代提配方、使用者泡了給回饋、系統收斂到使用者心目中的理想配方。

---

## 1. 大方向 —— 是演化，不是重寫

整個 Phase 10 的歷程已經顯示:IDEAL 一直是不確定的（medium_light 重推過、light provisional、medium/moderately_dark 是 placeholder）。誠實的處境是 —— 使用者在**搜尋**他的理想，不是我們**已知**它。一個搜尋偏好空間的產生機，才是誠實的框架。

現有零件剛好就是產生機需要的:**Layer 1+2 = 模擬器**（旋鈕→預測風味）、**optimizer = 提案器**。唯一要變身分的是 **IDEAL** —— 從「手設的固定靶」變成「被一代代回饋逼近出來的移動靶」。Phase 1–5.5 不浪費。

它順手解掉幾個爛攤子:
- **tim ⭐2/⭐4**：迴圈不需要「懂」⭐2 為何難喝，只要往 ⭐4 移、離 ⭐2 遠。
- **「沒有客觀最好」**：搜尋「你的」偏好正是對這件事的正解。
- **placeholder 焙度**：每個焙度各跑各的迴圈，IDEAL 從「我宣稱」變「我泡出來的」。

---

## 2. 取樣成本是主宰 —— (1+λ)，不是 GA

一次「評估」= 實際泡一杯、喝、評分 → 一天 1–3 個資料點。經典大族群基因演算法（大族群 × 多代）會收斂好幾個月。

正確的形狀是 **(1+λ) 演化 / 符號爬山**:留一個冠軍配方、每代提幾個變異、贏家接棒。收斂量級約 **10–30 杯**。第一代由現有模型 seed（不是亂槍打鳥）。

關鍵字 **探索 vs 利用**:現在的 optimizer 只會「利用」（給當前 IDEAL 的最佳解）。產生機要的新能力是「探索」—— 故意提偏離的配方，目的是**學**偏好、不是討好當前估計。

---

## 3. 三杯循環 `[實驗1, 實驗2, 最佳]`

每 3 杯一個循環:

1. **實驗1** —— 冠軍的擾動 A
2. **實驗2** —— 冠軍的擾動 B（一天一杯、有時間 → 可看完實驗1 的回饋再定）
3. **最佳** —— 程式吃完兩個實驗的回饋後，推出的當前最佳估計

**為何成立:**
- **重泡冠軍**取代「記住冠軍」—— 第 3 杯永遠落在使用者的 2 杯記憶窗內，不必記超過 2 杯前的味道。
- 2 杯記憶 + 此排序 → 第 3 杯能**同時**跟實驗1、實驗2 比 → 一個循環得到數組成對比較（exp1↔exp2、exp2↔best、best↔exp1，跨循環 best↔下個 exp1）。
- 最佳杯**三職**:給使用者一杯能好好喝的、把味覺記憶重新錨定、檢查「我宣稱的最佳，舌頭還同意嗎」。
- 擾動幅度照**排程**（早期大膽、後期收細，像降溫排程）；早期變異建議一次只動一兩個旋鈕（歸因才乾淨）。

---

## 4. 問卷 —— 全 `>/=/<`、靠記憶、模型預填

每泡完一杯，對照**上一杯**:

- **整體偏好**（搜尋引擎）：這杯 vs 上一杯 = 較好 / 差不多 / 較差。
- **逐屬性差異**（校準模型 + 抓方向錯）：10 個屬性用 `models.sensory.AXIS_VIEW` 收成 ~6–7 群（酸 / 甜 / body / 苦 / 澀 / 焙烤 + character）來問；每群 更多 / 一樣 / 更少。**模型先預填它的預測**，使用者只改不準的 → 一杯回饋變成 10 秒的事，每個修正都是高價值訓練點。
- **自由欄**：模型問不到的（「失去淺焙亮度」「尾韻乾」）。

**設計鐵則:**
- **全部 `>/=/<`，不寫程度。** 靠模糊的味覺記憶撐不起「程度」判斷；ordinal 與「靠記憶」是天生一對 —— 丟掉的是本來就會是假精確的東西。
- 「一樣 / 差不多」是**有用的資料**（「這改動沒動到那屬性」/「這方向是平的」），不是沒填。
- **模型表徵（10 屬性）≠ 問卷粒度（~6 群）** —— 兩者解耦；問卷只問人真的分得出來的。

## 5. 搜尋演算法

- 留一個**冠軍**配方。每代提 **λ=2** 個變異（冠軍的旋鈕擾動，模型 seed）。
- 使用者只回答「新的比較好嗎」→ 贏家接棒。**此演算法從頭到尾用不到「程度」** —— 跟「不寫程度」剛好對上，不是妥協。
- 符號只給**方向**、不給距離 → 步長用**排程**決定（早大後細），收斂速度由排程定、不由資料定。
- ordinal 回饋能抓「模型把方向搞反了」，但**不能**校準斜率大小 → Layer 2 維持粗先驗（與 Phase 10 定位一致）。
- 搜尋維度 = `dose × dial × steep`；溫度是**輸入**、不搜尋（見 [`PHASE10_STEP4_LAYER1.md`](PHASE10_STEP4_LAYER1.md) §8）。

## 6. Claude 的介入 —— 三層 + 三紀律

**原則:迴圈必須能在沒有 Claude 的情況下自己跑。** Claude 是例外處理器，不是迴圈的一步。恰當的介入 = 盡量少出現，只接程式做不到的事。

**三層:**
1. **程式 · 每杯 · 全自動** —— 問卷進、成對比較記錄、更新冠軍、提下兩杯實驗。使用者可連續數週不開對話。
2. **程式舉旗 · 邀請 Claude** —— 程式自己偵測「模型方向錯了」（它預測某屬性 Δ、使用者回報相反的 Δ —— 純機械比對），記一個 **flag**、**不自己修**。flag 累積夠了，使用者開對話 → Claude 一次看一批。
3. **Claude 診斷 · 動手** —— 做程式做不到的:讀自由欄的話、判矛盾根因（Layer 1 TDS 算錯 / Layer 2 係數方向反 / cotter 沒涵蓋的結構盲點）、決定怎麼辦。

**三紀律（讓「介入恰當」）:**
1. **分清「模型錯」vs「偏好變了」。** 逐屬性回報與模型矛盾 → 模型錯 → Claude 的事；屬性都對、但整體偏好換一杯 → 偏好在移動 → 迴圈本來就會處理、不關 Claude。問卷兩層就是為了切開這兩件事 —— 沒有逐屬性層，就沒有觸發 Claude 的依據。
2. **一次矛盾不算數，要重複才動。** 靠記憶的比較有雜訊。單一矛盾只記、不動；Claude 只在**同方向矛盾反覆出現**才當真 —— Claude 是 pattern-vs-雜訊的過濾器 → 批次看、非每杯。
3. **每筆 Claude 改動留痕、可回退、使用者看得懂。** 小事（調 IDEAL / 權重）→ 改 data 檔 + 一行 changelog。結構性（Layer 2 表達不出來的盲點）→ 不能用改資料蒙混；講清楚、提一個程式改法或一個受控對照實驗、要使用者點頭。

> Tier-3 診斷**不需要**另建「風味互動表」—— Step 5.5 把 10 個屬性各自對 (TDS,EY) 回歸，cotter 的值本就是消費者感受後的、互動已內建於資料（見 [`PHASE10_STEP5_5_ALL_ATTRIBUTES.md`](PHASE10_STEP5_5_ALL_ATTRIBUTES.md) §1）。

## 8. 已知限制 / 開放項目

- **靠記憶的成對比較有雜訊** —— 設計上接受；靠「不過度相信單一比較」+ 步長排程吸收。
- **ordinal 不校準斜率大小** → Layer 2 維持粗先驗；相對斜率（`ALPHA`/`GAMMA`/`K_RATIO`）由迴圈長期實測修正，不靠手調。
- **多旋鈕同時變 → 歸因不清** —— 早期變異一次只動一兩個旋鈕。
- **placeholder 焙度**（medium / moderately_dark）要等該焙度有 feedback 才真錨定。
- **Hoffman 焙度標籤** —— 對話中議定**保留 `medium_light`**:在 Phase 10 架構下 relabel 純 cosmetic（絕對尺度會抵銷），且現分法正確編碼「tim（Nordic）比 Hoffman（Square Mile）更淺」的順序。**開放**:待使用者確認自己實際泡哪幾個焙度、⭐5 那支豆與 tim 是否明確不同級 —— 這個定了，焙度槽的歸屬才有定論。
- **絕對 TDS/EY 不重要**（系統錨定 → 抵銷）；輸出不該再把「預測 TDS」當頭條，標成粗估或只顯示相對位置（Step 6 順手）。
